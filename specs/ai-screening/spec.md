# AI 文章筛选

筛选国内公司技术博文，保留有具体做法和验证结果或技术取舍的 AI 工程应用实践。过滤模型发布、训练或跑分、广告软文、开源软件分享和其他无关内容。用模型或开源工具解决实际问题的工程复盘仍可收录。

采集和正文补抓完成后，`pnpm ai:screen` 把标题和清洗后正文开头最多 1000 个 Unicode 字符交给模型。没有可用正文时只评估标题，证据不足就待复核。模型不读取摘要、文章后续内容或链接。相同输入、规则和模型配置复用已有结论。正文开头变化时重新评估。

结论保存在带校验和的文章快照里。导出统一应用结论，过滤后的文章仍可补抓和复核。看板、搜索、详情、公开 JSON 和订阅使用同一批文章。人工覆盖写在 `config/overrides.json` 的 `articles` 中，例如在指定文章的配置里加入 `"aiScreen": "keep"` 和 `"reason": "工程复盘，人工复核保留"`。原有来源验证、人工隐藏和合并规则继续生效。

在 GitHub 仓库 **Settings → Secrets and variables → Actions** 配置：

| 类型     | 名称                   | 值                                                                  |
| -------- | ---------------------- | ------------------------------------------------------------------- |
| Variable | `RADAR_AI_API_URL`     | 完整 HTTPS 地址，例如 `https://api.example.org/v1/chat/completions` |
| Variable | `RADAR_AI_LLM`         | 服务商提供的模型 ID                                                 |
| Variable | `RADAR_AI_SCREEN_MODE` | 先设为 `shadow`                                                     |
| Secret   | `RADAR_AI_API_KEY`     | 接口密钥                                                            |

接口需支持 Chat Completions 的 JSON 对象输出。只有筛选步骤拿到密钥。手动运行 **Collect and publish** 时启用 `collect` 可验证接线；定时采集也会执行筛选。每次默认最多评估 100 篇，并发 3。运行摘要给出保留、过滤、待复核、待处理和失败数，可在 `data` 分支快照的 `aiScreen` 字段复核单篇结论。

待历史回填结束，抽查误判并确认过滤范围后，将模式改为 `enforce`，重新发布。此时只公开人工或 AI 判为保留的文章。接口超时、限流或返回无效结果时，已有结论继续生效，新文章等待重试。改回 `off` 并重新发布可恢复原有收录范围，无需重抓。

验收：验证 1000 字边界、缓存、失败回退，以及同一筛选结论对公开产物的影响。真实模型效果以 `shadow` 的实际结果为准。
