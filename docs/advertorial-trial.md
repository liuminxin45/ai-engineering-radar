# 软文标记试运行

试运行只标记疑似软文，文章继续展示，保留在搜索和订阅中。列表条目右下角显示红色“疑似软文”标签，点击后进入文章详情，查看命中原因和标题、摘要片段。

## 判断范围

现有采集只保留必要元数据和原站短摘要。本版规则只分析这些内容，不抓取或保存全文，不调用模型服务。每条结果注明判断范围，未标记也不代表全文已经审查。

明确以福利、优惠、购买注册引流或活动报名为主的标题会标记。产品升级、效果口号和引流文案需要组合命中；摘要含具体技术机制、测试条件、性能数据或技术取舍时，保留而不标记这类模糊信号。公司名、产品名、单独的发布公告或文末推广不能单独触发标记。

标题没有明确营销信号且缺少摘要时，记录为材料不足，不显示红色标签。规则只作初筛，会漏掉隐蔽营销，也可能误标正常分享，需要人工复核。后续是否引入全文判断或自动隐藏，另行决定。

## 复核与更正

公开的 `/data/advertorial-review.json` 包含全部疑似条目、复核链接、原因、命中片段，以及材料不足的条目数。文章 JSON 中的 `advertorial` 记录同一结果；`classification` 和 `publicationStatus` 继续负责原有收录状态。

维护者在 `config/overrides.json` 的 `articles` 中按文章 ID 更正。例如，将下方占位 ID 换成复核条目的实际 ID：

```json
{
  "schemaVersion": 1,
  "articles": {
    "替换为实际文章ID": {
      "advertorial": "cleared",
      "reason": "人工复核：正文包含完整实现和测试条件，取消疑似软文标记。"
    }
  },
  "merges": []
}
```

`cleared` 取消标记，`suspected` 人工补充标记，均要求填写原因。单独更正软文标记不会修改文章收录、主题或发布状态。人工结论优先于自动规则；删除该条人工配置后，下一次采集或导出恢复规则判断。

## 更新与回退

每次采集和导出都会计算规则结果，因此历史条目与新条目使用相同版本，无需重新采集全文。导出同时更新列表、详情、文章 JSON 和复核清单。规则自动结论随标题、摘要和规则版本重新计算。

旧快照可以不含 `advertorial` 字段，导出时补充结果。采集会保存结果；取消人工配置后，采集和导出均会清除旧的人工结论。需要停止试运行时，撤销本次代码提交并重新发布，原有文章快照和稳定 ID 仍可使用。
