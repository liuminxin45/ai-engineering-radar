# 运行维护

## 每日采集

CSDN 使用 RSSHub 发现文章并先尝试普通请求，失败时由独立 Camoufox 服务取得 HTML。两个服务仅在采集期间启动；分层接口、版本及运行方式见[获取层维护](acquisition.md)。

默认每天 UTC 01:17（北京时间 09:17）运行。调度文件必须位于默认分支。GitHub 在繁忙时可能延迟或丢弃调度任务；公开仓库长期无活动时，定时工作流也可能停用。遇到停用，在 Actions 页面重新启用并手动运行一次，不把本地手动验证视为定时触发成功。

每次任务输出来源状态、成功数量和来源验收表。网站右上角显示数据快照时间，最近采集成功时间见 `/data/sources.json`；`/data/health.json` 可用于外部监测。故障通知使用 GitHub Actions 原有通知机制。

每日任务执行 `pnpm ingest --daily`，默认使用增量模式。仍需检查来源目录才能发现新内容；支持条件请求的入口沿用 ETag / Last-Modified，目录未变化时返回 304。文章位置保存目录元数据的 `listingHash`，用于区分新增、修改和未变化的条目。旧快照没有该字段时按已有元数据建立基线，不清空历史记录，也不按发布日期截断，避免遗漏补发或回填的文章。

未变化的文章跳过详情页元数据与成功正文。分页目录遇到整页已收录文章后停止继续翻页；显式全量模式仍按来源配置的数量上限检查旧页。目录元数据补充失败时保存 `metadataPending`，下次看到该条目时继续补充。

正文队列包含新增、目录有变化、正文不可用、正文不完整及上次刷新失败的博文。增量模式忽略这些失败记录的 7 天重试时间，每次运行重试一次；即使来源目录返回 304 或请求失败，也从快照继续重试正文。成功且未变化的正文不因 30 天检查时间到期而重新抓取；解析引擎或规则升级仍会触发重新处理。

每日队列不再限制为 40 篇，避免历史失败文章一直没有重试机会。优先处理新增与有变化的文章，随后按上次尝试时间处理重试项。每处理 20 篇保存一次快照；再次失败保留已有正文，并记录错误与最近尝试时间。任务摘要分别输出新增、修改、未变化及本轮正文结果。

目录变化后的待刷新正文通过 `refreshPending` 随快照保存。即使中途退出，目录哈希已经更新而正文尚未刷新，下次仍会继续处理。成功取得新正文后清除此标记。

`--force` 强制检查来源，仍使用增量内容策略。需要主动重抓时，执行 `pnpm ingest --full`，也可以附加 `--source=来源ID`；该命令强制检查所选来源并刷新其历史正文。只重新发布且不采集时，继续关闭工作流的 `collect` 输入。

## 阅读界面验收

发布前检查 PC 的横向多列和手机的单列滑动。每列独立上下滚动，顶部公司导航能定位到对应列。聚焦看板后，左右方向键也能切换列。手机展开搜索后仍能关闭，并且不会增加整页横向溢出。文章详情和 About 保持正常纵向阅读。

在公司导航、面板标题和列间空隙上下滚动鼠标，确认看板先快后缓停，约 180 毫秒完成单次过渡，公司高亮和 URL 随之更新。同向连续输入累计距离，反向输入立即接管未完成的动画，边界停止。触控板斜向输入只取主轴，Ctrl / Meta 加滚轮不被页面拦截。文章区域保持原生上下滚动，到底后也不横移。手机触摸仍能左右滑动并吸附到列。点击、键盘、历史恢复和窗口调整应中断旧动画；系统开启“减少动态效果”时直接完成定位，包括动画中切换偏好。

搜索结果仅显示在弹窗内，输入不改变面板列表或 URL。用关闭按钮、Esc 或桌面背景关闭弹窗后，再次打开时输入应为空。当前公司列和已加载批次需要在刷新及浏览器前进后退后恢复。可用 `?company=dewu&page=2` 检查直达链接；`page=2` 表示当前列已加载两批，共最多 40 篇文章。文章始终最新优先，旧链接中的 `sort=oldest` 会被清理。列表不显示数量，触底时自动追加一批。确认追加后不会在没有继续滚动时连续加载所有文章。

核对 ATOM/RSS 小窗中的两个全站链接与复制结果，检查复制失败提示、Esc、点击外部关闭和焦点恢复。验证深浅色切换及刷新后的保存、GitHub 图标链接、博文标题进入本站阅读页、原文入口及项目子路径直达。确认界面没有更多菜单、排序控件、公司订阅入口、来源目录、列表数量和底部切换控件；更新时间位于右上角。检查链接悬浮动画和键盘焦点。截图与人工体验只是界面证据，发布成功仍以构建、部署及线上检查结果为准。

## 数据分支

数据分支包含 `snapshot/manifest.json`、`snapshot/articles/`、`snapshot/sources/` 和 `snapshot/bodies/`。v2 清单记录文章、来源和正文数量及 SHA-256，正文另保存 HTML 校验和。v1 快照仍可读取，下次保存升级为 v2。每次从完整快照恢复，不依赖临时缓存或过期 Artifact。来源迁移会保留仍有有效来源支持的正文，清理失去文章或来源关联的正文。

采集先写工作副本，经数据校验、构建及浏览器验收后，使用普通 Git 提交推送。写入互斥且禁止强推。数据提交不会触发 `main` 分支工作流。

本地数据命令使用快照目录旁的 `.lock` 文件互斥。异常退出后，先查看锁内的进程号并确认进程已结束，再删除该锁文件；不要删除快照目录。每日采集使用 `--daily`，避免运行耗时造成 24 小时轮询间隔逐日漂移，同时保留 HTTP 条件请求。

损坏或无法识别的版本会立即失败，不自动重建空库。需要迁移时先实现显式迁移并保留旧快照提交。

本批国内迁移使用 `pnpm data:migrate-domestic`。它先验证旧快照完整性，再按当前国内注册表删除海外文章和来源状态，并将国内账号文章直接纳入索引。重复执行不会重建数据。恢复旧版含海外来源的快照后，必须先执行迁移再校验和发布。

该命令也处理 `packages/source-registry/replacements.ts` 明确登记的来源替换。维护者明确移除且没有替代的来源登记在 `sourceWithdrawals`，同时移除公司栏目；恢复旧快照时会再次清理这些来源的状态与独占文章。标记为 `referenceOnly` 的参考入口只删除空状态；若发现关联文章则报错。此类清理允许保留源维持暂停状态，不要求重新启用历史源。只有替代来源已经核验、启用并存在成功采集记录及已发布文章，才移除旧源位置与状态；仅剩旧源位置的文章退出快照，仍有其他有效位置的文章保留原 ID。缺少替代证据时迁移失败，旧快照不会被覆盖。恢复替换前的快照后，发布流程会重新执行同一迁移；恢复操作不会重新上线已移除的旧源。

每家公司在注册表中恰好保留一个来源。更换来源时，先用新源配置在隔离快照完成真实采集，将成功状态与文章合入待迁移的原快照，再移除旧源并执行迁移。准备好代码与数据提交后，可用 Git 原子推送同时更新 `main` 和 `data`，避免发布过程读到缺少替代证据的中间快照。若远端数据已经变化，停止发布，基于最新快照重新准备，禁止强推覆盖。恢复更早且缺少新来源的快照时，也需要先在临时配置中补齐替代采集，或改用已经完成替换的合法快照。

## 恢复数据

1. 停止新的手动采集，等待正在执行的发布完成。
2. 检查 `data` 分支历史，找到通过校验的快照提交。
3. 在数据分支使用 `git revert` 撤销损坏提交，或从指定提交恢复 `snapshot/` 并创建新提交；不用强推覆盖历史。
4. 运行数据校验，再手动执行关闭 `collect` 的发布。

网站部署失败时，已经保存的合法数据仍可重用。构建失败或全部来源失败时，已部署的网站保持上一个版本。

## 来源故障

采集成功与近期活跃分别核验。来源 JSON 中的 `latestPublishedAt` 表示已公开收录文章的最近发布日期，不用采集时间替代。来源核验和实测结果还可查看仓库内的[来源验收表](source-acceptance.md)。尚无可靠替代的过时渠道以 `suspended` 暂停新增并保留历史；已完成替换的旧渠道从注册表与快照移除。健康快照的成功和失败数量只统计启用渠道。

身份核验与采集成功独立。403、robots 禁止、验证码、入口不可用或解析不到文章均不能标记为接入成功。改变入口或适配器需要重新执行该来源的真实采集。

单来源诊断可运行 `pnpm ingest --force --source=来源ID`。身份待确认的入口只检测可达性，绝不自动升级认证。未获取到文章的来源不会更新最近采集成功时间。

## 发布安全

生产构建和订阅导出默认使用 `https://liuminxin45.github.io/ai-engineering-radar`。自定义部署用 `SITE_URL` 设置公开站点根地址，用 `BASE_PATH` 设置路径前缀；根路径部署显式设为空。页面元数据与订阅使用同一地址解析逻辑，localhost 或回环地址会在构建、导出前报错。开发服务器地址与公开订阅地址分别配置。

PR 工作流使用固定夹具和只读权限；公开部署工作流仅运行本仓库默认分支代码。构建产物必须通过公开内容检查，禁止发布测试夹具、私人路径和凭据。首批不使用模型服务，不需要模型密钥。

HTTP 采集器限制公开 HTTP(S) 地址、来源域名和重定向，拒绝私有地址；不接受用户传入临时抓取 URL。正文附属域名须在来源的 `bodyHosts` 中明确登记。遵守 robots 和访问限制，网络响应只在内存中解析，不提交原始页面。正文补抓与重试命令见[阅读页维护说明](article-reader.md)。

## 论文功能下线

当前仅收录博文。发布工作流恢复旧快照后运行 `pnpm data:migrate-domestic`，移除历史论文、论文来源状态及失效重复引用，再保存经过校验的快照。博文 ID、正文及有效来源位置保留。旧论文链接不再生成详情页，旧 `?type=paper` 链接显示博文。历史数据仍可通过 `data` 分支的 Git 历史审计。
