# P0 技术设计

## 数据流

国内官方账号注册表 → RSS / Atom 或独立站点适配器 → 元数据规范化 → 去重 → 直接建立索引 → 版本化 JSON → 静态页面、JSON、RSS / Atom → GitHub Pages。

首批只保留国内公司，已核验且启用的官方账号文章直接进入索引。身份核验、去重和数据校验继续执行，不做内容相关性筛选、模型审核或自动主题分类。博文在本站统一排版阅读并保留原文入口。

## 实体与状态

Company 表示国内公司或品牌，Publisher 表示具体官方发布主体，Source 表示实际采集入口。vivo 的多个渠道分别保留来源记录；已经完成替换的旧源退出当前注册表与公开索引。公司归属依据账号发布主体，不依据托管平台域名。

Article 保留稳定 ID、发布主体、公司、规范 URL、日期、作者、短摘要与全部发布位置。已核验官方账号的文章使用 `source-index-1` 标记直接收录，保留已有数据字段以完成旧快照迁移。人工隐藏用于更正、版权请求或确认的重复记录。

当前仅收录博文，缺少 `contentType` 的旧记录按博文处理。历史论文字段仅供读取旧快照，发布前迁移会移除论文记录及来源状态，保留博文稳定 ID。公开索引、搜索和订阅仅包含博文。

来源身份状态与优先级、网络状态独立。未认证的账号不参与文章采集。被暂停的来源停止新增，但已发布历史保留；撤销身份后仅有该来源支持的文章退出公开索引。明确完成替换的来源通过迁移移除，替代渠道必须具备官方身份、成功采集记录与已发布文章。移除旧位置后仍有其他有效位置的文章保留原 ID；仅由旧源支撑的文章及其详情退出发布。

## 去重与收录

URL 去掉明确的跟踪参数，保留影响文章身份的查询参数。来源内 GUID、规范链接和明确的跨平台原文关系用于确定去重。相似标题只保留候选提示，不自动合并，也不阻止不同地址的文章展示。

文章不需要命中 AI 关键词或工程机制词才能收录。来源身份仍需核验，社区账号必须绑定稳定账号 ID，并按平台适配器验证发布主体。

## 存储与发布

正文获取使用独立文档接口，CSDN 编排依次尝试 RSSHub HTTP 与 Camoufox 浏览器服务。提供器只获取文档，由同一解析层校验、清洗和生成目录；快照存储与静态页面不依赖具体获取方式。浏览器服务只在采集任务期间运行。接口与扩展方式见[获取层维护](acquisition.md)。

按发布主体分片保存主文章，来源单独保存状态，以免跨平台重复损失发布路径。所有文件属于同一快照，由清单校验和连接。临时快照验证后再替换工作副本，远端以 Git 提交提供一致性和历史恢复。

Next.js 在构建时生成首页、About 和每篇文章详情。搜索、公司列定位和分批显示在浏览器执行。URL 保存公司列定位和分批显示状态。来源配置、核验材料和检测结果保留在仓库文档与公开 JSON 中，网站不展示来源目录。静态 JSON 接口不模拟动态 API。

国内迁移命令先验证旧快照的结构、数量与校验和，再删除不在国内注册表中的公司文章和来源状态。保留文章稳定 ID，将国内旧的待复核及未收录条目改为直接收录。迁移后的公开构建不包含海外文章和来源；Git 历史保留以便审计与恢复。

原方案的 SQLite、FTS5、ORM、内部采集 HTTP 接口和 Docker 常驻服务由 Actions 批处理与 JSON 快照替代。GitHub Pages 负责托管文件，应用不控制其缓存头。

## 多面板阅读

首页仅提供博文看板，搜索覆盖全部博文。整个看板横向滚动，每列独立纵向滚动。PC 在同一屏内并排展示多列；手机显示一列及下一列边缘，支持左右滑动和顶部公司导航。

公司导航、面板标题及列间空隙将鼠标滚轮映射为看板横移：向下向右，向上向左。触控板使用绝对值较大的轴，保留方向与小数增量，不叠加两个轴；行和页单位分别按行高、视口宽度换算。横移采用 180 毫秒的三次缓出动画，先快后缓停。连续同向输入累计目标，从当前位置衔接；反向输入取消未完成的尾段，立即响应新方向。系统开启“减少动态效果”时直接定位，偏好在动画中变化时也会立即完成。桌面不强制吸附到整列。到达两端后不再拦截滚轮，Ctrl / Meta 加滚轮交由浏览器处理。

文章区域保留原生纵向滚动，即使到底部也不转为横移；触控板原生横向手势继续由浏览器处理。正文滚动、触摸、点击、键盘、历史恢复或窗口调整会接管尚未完成的动画，避免旧目标覆盖新操作。手机触摸开始时恢复原有的列吸附。当前位置继续同步公司高亮与 URL，不增加浏览器历史记录。

顶部只保留紧凑工具栏与公司导航，搜索统一由右上角图标打开，数据更新时间放在右上角。每个面板标题栏只显示“最新文章”或公司名称，不显示说明和最新日期；桌面与手机的最小高度统一为 48px。文章列表保持标题和完整日期（`yyyy/MM/dd`），副信息不再重复显示公司或采集渠道。博文标题打开本站 `/articles/{id}/`。缺少发布日期时，发现时间的说明保留在无障碍标签中。列表不显示文章数量，也不重复设置“原文”按钮。详情页继续展示发布主体及全部发布位置。About 和文章详情使用正常的纵向阅读布局。

博文正文由独立解析引擎清洗，按篇保存 HTML、目录、规则版本和完整性状态。阅读页提供顶部原文入口、目录、进度和图片预览，返回时恢复看板位置。快照 v2 对正文文件和 HTML 分别校验，兼容没有正文的 v1 数据；首页与搜索只加载元数据。详情见[阅读页维护](article-reader.md)。

搜索覆盖标题、摘要和作者。搜索窗口复用 `neo.github.io` 的原生 dialog、淡入缩放、模糊背景、聚焦微移和标题下划线效果，手机全屏展示。按钮与 GitHub 图标使用相同的透明背景和悬浮高亮。输入框立即聚焦，结果按需加载并延迟 300 ms 查询，每批显示 10 条；支持关键词高亮、方向键、回车、Esc 与 Ctrl/⌘ + K。关闭后恢复按钮焦点，系统减少动态效果时关闭动画。搜索结果仅显示在弹窗内，输入不修改看板列表或 URL。关闭弹窗时清空输入，再次打开为空。文章固定按最新优先展示，不提供排序控件；旧链接的 `sort` 参数会被忽略并清理。每列初始显示 20 篇，滚动到底部时自动追加 20 篇。自动加载只增加当前列的可见条数，不请求源站或动态文章 API。

首页保留以下 URL 参数：

| 参数 | 含义 |
| ---- | ---- |

| `q` | 兼容旧链接的看板筛选词；搜索弹窗不读写此参数 |
| `company` | 定位公司列，其他公司列仍可横向浏览；省略时定位“最新”列 |
| `page` | 当前列已加载的批次数，每批 20 篇，默认 1 |

刷新、直达及浏览器前进后退从 URL 恢复当前列和当前列已加载批次，旧链接的 `q` 仍兼容看板筛选。自动追加使用当前历史记录保存批次，不增加后退步骤；追加后保留阅读位置，再次向下滚动到新底部才追加下一批。工具栏平铺深浅色切换、ATOM/RSS 和 GitHub 图标，不再使用更多菜单。订阅小窗显示两种全站订阅的完整链接，各自提供复制操作；支持关闭按钮、Esc 和点击外部关闭，关闭后恢复焦点。复制失败时保留可手动复制的地址并显示提示。外观默认跟随系统，用户切换后保存明确的深色或浅色选择。

界面沿用个人博客的共享组件库、配色和链接下划线动画。键盘用户可以操作搜索、公司导航和工具栏；聚焦看板后可用左右方向键切换列，手机也可以点击公司名称定位。系统深浅色、可见焦点和减少动态效果同时适用于看板。横向滚动限制在看板和公司导航区域内，不扩宽页面文档。桌面和手机的工具栏均显示数据快照的完整日期和时分，采用北京时间。
