# P0 技术设计

## 数据流

来源注册表 → RSS / Atom 或独立站点适配器 → 元数据规范化 → 去重 → 规则或可选模型分类 → 版本化 JSON → 静态页面、JSON、RSS / Atom → GitHub Pages。

采集与网站读取解耦。浏览器只读取经过发布筛选的元数据，原文仍在原站阅读。

## 实体与状态

Company 表示公司或品牌，Publisher 表示具体官方发布主体，Source 表示实际采集入口。Google 与 DeepMind 分发布主体，共用 Google 公司归属；vivo 的多个渠道、得物的官网与腾讯云专栏保留各自来源记录。

Article 保留稳定 ID、发布主体、公司、规范 URL、日期、作者、短摘要、分类与全部发布位置。仅 `accepted` 且 `published`，并且存在可信来源关系的文章可公开导出。

来源身份状态与优先级、网络状态独立。未认证的账号不参与文章采集。被暂停的来源停止新增，但已发布历史保留；撤销身份后仅有该来源支持的文章退出公开索引。

## 去重与分类

URL 去掉明确的跟踪参数，保留影响文章身份的查询参数。来源内 GUID、规范链接和明确的跨平台原文关系用于确定去重。相似标题进入待复核，避免合并同名系列文章。

规则分类保留判断依据和版本。判定依据为元数据中的 AI 关联、工程行动及实现机制；无法确定时保持待复核。模型只处理不确定内容，输出结构及证据必须校验；错误不得变成自动发布。

## 存储与发布

按发布主体分片保存主文章，来源单独保存状态，以免跨平台重复损失发布路径。所有文件属于同一快照，由清单校验和连接。临时快照验证后再替换工作副本，远端以 Git 提交提供一致性和历史恢复。

Next.js 在构建时生成首页、来源目录和每篇文章详情。搜索、组合筛选、排序和分页在浏览器执行，URL 保存筛选状态。静态 JSON 接口不模拟动态 API。

原方案的 SQLite、FTS5、ORM、内部采集 HTTP 接口和 Docker 常驻服务由 Actions 批处理与 JSON 快照替代。GitHub Pages 负责托管文件，应用不控制其缓存头。
