# P0 技术设计

## 数据流

国内官方账号注册表 → RSS / Atom 或独立站点适配器 → 元数据规范化 → 去重 → 直接建立索引 → 版本化 JSON → 静态页面、JSON、RSS / Atom → GitHub Pages。

首批只保留国内公司，已核验且启用的官方账号文章直接进入索引。身份核验、去重和数据校验继续执行，不做内容相关性筛选、模型审核或自动主题分类。博文在本站统一排版，顶部可打开原文；正文状态不影响索引收录。

## 实体与状态

Company 表示国内公司或品牌，Publisher 表示具体官方发布主体，Source 表示实际采集入口。vivo 的多个渠道分别保留来源记录；已经完成替换的旧源退出当前注册表与公开索引。公司归属依据账号发布主体，不依据托管平台域名。

Article 保留稳定 ID、发布主体、公司、规范 URL、日期、作者、短摘要与全部发布位置。已核验官方账号的文章使用 `source-index-1` 标记直接收录，保留已有数据字段以完成旧快照迁移。人工隐藏用于更正、版权请求或确认的重复记录。

`contentType` 区分 `blog` 与 `paper`，旧记录缺少此字段时按博文处理，无需迁移快照。论文的 `companyIds` 保存已核实的公司归属，至少一项且不能重复，所有 ID 均须存在于公司注册表；`companyId` 继续表示发布主体所属公司。署名归属与来源身份分别保存。来源可声明默认类型，混合目录由适配器逐条指定；人工更正支持类型和归属字段。公开导出与订阅保留论文的多家公司归属。

来源身份状态与优先级、网络状态独立。未认证的账号不参与文章采集。被暂停的来源停止新增，但已发布历史保留；撤销身份后仅有该来源支持的文章退出公开索引。明确完成替换的来源通过迁移移除，替代渠道必须具备官方身份、成功采集记录与已发布文章。移除旧位置后仍有其他有效位置的文章保留原 ID；仅由旧源支撑的文章及其详情退出发布。

## 去重与收录

URL 去掉明确的跟踪参数，保留影响文章身份的查询参数。来源内 GUID、规范链接和明确的跨平台原文关系用于确定去重。相似标题只保留候选提示，不自动合并，也不阻止不同地址的文章展示。

文章不需要命中 AI 关键词或工程机制词才能收录。来源身份仍需核验，社区账号必须绑定稳定账号 ID，并按平台适配器验证发布主体。

## 存储与发布

按发布主体分片保存主文章，来源单独保存状态，以免跨平台重复损失发布路径。所有文件属于同一快照，由清单校验和连接。临时快照验证后再替换工作副本，远端以 Git 提交提供一致性和历史恢复。

Next.js 在构建时生成首页、About 和每篇文章详情。搜索、公司列定位和分批显示在浏览器执行，URL 保存状态。来源配置、核验材料和检测结果保留在仓库文档与公开 JSON 中，网站不展示来源目录。静态 JSON 接口不模拟动态 API。

国内迁移命令先验证旧快照的结构、数量与校验和，再删除不在国内注册表中的公司文章和来源状态。保留文章稳定 ID，将国内旧的待复核及未收录条目改为直接收录。迁移后的公开构建不包含海外文章和来源；Git 历史保留以便审计与恢复。

原方案的 SQLite、FTS5、ORM、内部采集 HTTP 接口和 Docker 常驻服务由 Actions 批处理与 JSON 快照替代。GitHub Pages 负责托管文件，应用不控制其缓存头。

## 多面板阅读

首页顶部提供“博文 / 论文”两个轻按钮，默认博文。两类内容共用“最新”列和公司分列看板，搜索只作用于当前类型。论文按 `companyIds` 出现在各归属公司的列中，“最新”列只展示该条记录一次。切换类型时保留公司与关键词，重置各列批次和纵向滚动。整个看板横向滚动，每列独立纵向滚动。PC 在同一屏内并排展示多列；手机显示一列及下一列边缘，支持左右滑动和顶部公司导航。

顶部只保留紧凑工具栏与公司导航，搜索统一由右上角图标打开，数据更新时间放在右上角。文章列表保持标题、来源和日期，博文标题及搜索结果在当前标签页打开 `/articles/{id}/`，论文标题保留原站跳转。列表不显示文章数量。博文阅读页的排版、目录、阅读进度和图片预览参照个人博客，顶部提供原文入口；返回时从浏览器历史记录恢复公司列、各列批次、纵向滚动和横向位置。About 和文章详情使用正常的纵向阅读布局。

正文解析采用独立的 `packages/article-parser/` 引擎，输入 HTML、Markdown 或发布方块级 token，输出清洗后的 HTML、目录和完整性状态。站点选择规则保存在独立 JSON，结构化数据提取器提供扩展接口，均不执行原站脚本。正文按文章 ID 单独保存；快照 v2 对正文文件和 HTML 分别校验，兼容读取 v1。构建时按篇加载，首页及搜索索引不包含全文。详细边界见[阅读页维护说明](article-reader.md)。

搜索覆盖标题、摘要和作者。搜索窗口复用个人站的弹窗、聚焦与悬浮动画，支持方向键、回车、Esc 及 Ctrl/⌘ + K；手机全屏展示，关闭后恢复按钮焦点。文章固定按最新优先展示，不提供排序控件；旧链接的 `sort` 参数会被忽略并清理。每列初始显示 20 篇，滚动到底部时自动追加 20 篇。自动加载只增加当前列的可见条数，不请求源站或动态文章 API。

首页保留以下 URL 参数：

| 参数      | 含义                                                      |
| --------- | --------------------------------------------------------- |
| `type`    | `blog` 或 `paper`；省略或无效时为博文，博文链接省略此参数 |
| `q`       | 中英文搜索关键词                                          |
| `company` | 定位公司列，其他公司列仍可横向浏览；省略时定位“最新”列    |
| `page`    | 当前列已加载的批次数，每批 20 篇，默认 1                  |

刷新、直达及浏览器前进后退从 URL 恢复关键词、当前列和当前列已加载批次。自动追加使用当前历史记录保存批次，不增加后退步骤；追加后保留阅读位置，再次向下滚动到新底部才追加下一批。工具栏平铺深浅色切换、ATOM/RSS 和 GitHub 图标，不再使用更多菜单。订阅小窗显示两种全站订阅的完整链接，各自提供复制操作；支持关闭按钮、Esc 和点击外部关闭，关闭后恢复焦点。复制失败时保留可手动复制的地址并显示提示。外观默认跟随系统，用户切换后保存明确的深色或浅色选择。

界面沿用个人博客的共享组件库、配色和链接下划线动画。键盘用户可以操作搜索、公司导航和工具栏；聚焦看板后可用左右方向键切换列，手机也可以点击公司名称定位。系统深浅色、可见焦点和减少动态效果同时适用于看板。横向滚动限制在看板和公司导航区域内，不扩宽页面文档。手机工具栏显示更新时间的时分，完整日期保留在时间提示中。
