# P0 技术设计

## 数据流

国内官方账号注册表 → RSS / Atom 或独立站点适配器 → 元数据规范化 → 去重 → 直接建立索引 → 版本化 JSON → 静态页面、JSON、RSS / Atom → GitHub Pages。

首批只保留国内公司，已核验且启用的官方账号文章直接进入索引。身份核验、去重和数据校验继续执行，不做内容相关性筛选、模型审核或自动主题分类。原文仍在原站阅读。

## 实体与状态

Company 表示国内公司或品牌，Publisher 表示具体官方发布主体，Source 表示实际采集入口。vivo 的多个渠道、得物的官网与腾讯云专栏保留各自来源记录。公司归属依据账号发布主体，不依据托管平台域名。

Article 保留稳定 ID、发布主体、公司、规范 URL、日期、作者、短摘要与全部发布位置。已核验官方账号的文章使用 `source-index-1` 标记直接收录，保留已有数据字段以完成旧快照迁移。人工隐藏用于更正、版权请求或确认的重复记录。

来源身份状态与优先级、网络状态独立。未认证的账号不参与文章采集。被暂停的来源停止新增，但已发布历史保留；撤销身份后仅有该来源支持的文章退出公开索引。

## 去重与收录

URL 去掉明确的跟踪参数，保留影响文章身份的查询参数。来源内 GUID、规范链接和明确的跨平台原文关系用于确定去重。相似标题只保留候选提示，不自动合并，也不阻止不同地址的文章展示。

文章不需要命中 AI 关键词或工程机制词才能收录。来源身份仍需核验，社区账号必须绑定稳定账号 ID，并按平台适配器验证发布主体。

## 存储与发布

按发布主体分片保存主文章，来源单独保存状态，以免跨平台重复损失发布路径。所有文件属于同一快照，由清单校验和连接。临时快照验证后再替换工作副本，远端以 Git 提交提供一致性和历史恢复。

Next.js 在构建时生成首页、来源目录、About 和每篇文章详情。搜索、公司列定位、时间排序和分批显示在浏览器执行，URL 保存状态。静态 JSON 接口不模拟动态 API。

国内迁移命令先验证旧快照的结构、数量与校验和，再删除不在国内注册表中的公司文章和来源状态。保留文章稳定 ID，将国内旧的待复核及未收录条目改为直接收录。迁移后的公开构建不包含海外文章和来源；Git 历史保留以便审计与恢复。

原方案的 SQLite、FTS5、ORM、内部采集 HTTP 接口和 Docker 常驻服务由 Actions 批处理与 JSON 快照替代。GitHub Pages 负责托管文件，应用不控制其缓存头。

## 多面板阅读

首页由“最新”列和各公司列组成。“最新”汇总所有已公开文章，公司列保留各自的文章列表。整个看板横向滚动，每列独立纵向滚动。PC 在同一屏内并排展示多列；手机显示一列及下一列边缘，支持左右滑动、公司导航和箭头定位。

顶部只保留紧凑工具栏与公司导航，手机搜索按需展开。文章列表保持标题、来源、日期和原文入口，详情页继续展示发布主体及全部发布位置。来源目录、About 和文章详情使用正常的纵向阅读布局。

搜索覆盖标题、摘要和作者。排序支持最新、最早优先，在更多菜单中切换。每列初始显示 20 篇，点击底部加载更多后再显示 20 篇。加载更多只增加当前列的可见条数，不请求源站或动态文章 API。

首页保留以下 URL 参数：

| 参数      | 含义                                                   |
| --------- | ------------------------------------------------------ |
| `q`       | 中英文搜索关键词                                       |
| `company` | 定位公司列，其他公司列仍可横向浏览；省略时定位“最新”列 |
| `sort`    | `newest` 或 `oldest`，默认最新优先                     |
| `page`    | 当前列已加载的批次数，每批 20 篇，默认 1               |

刷新、直达及浏览器前进后退从 URL 恢复关键词、当前列、排序和当前列已加载批次。切换公司列不改变全站与公司订阅路径。全站及每个公司继续同时提供 RSS 和 Atom。

界面沿用现有共享组件库。键盘用户可以操作搜索、公司导航、菜单和切换箭头；手机操作不依赖手势。系统深浅色、可见焦点和减少动态效果同时适用于看板。横向滚动限制在看板和公司导航区域内，不扩宽页面文档。
